# 购票申请恢复与运行配置说明

新购票申请按数据库时间设置首次`next_recovery_at`为当前时间加既有恢复间隔，避免正常排队中的命令在首次扫描时被提前重复投递。截止处理仍优先按原有截止条件执行，不等待恢复间隔后才释放容量预算。

后续认领租约、恢复扫描、故障退避、递增尝试令牌、发布确认与消费者幂等语义保持不变。会话身份和账号最新状态继续由Spring Security及数据库核对；连接池沿用已确认的连接状态复用配置，不改变事务隔离与数据库持久化要求。

当前默认值由业务配置文件和`.env.example`维护。清理历史测量内容不调整消费者数量、prefetch、Outbox窗口、扫描间隔、连接池容量、队列预算或库存锁协议，也不把历史实验参数作为部署建议。

相关业务及配置验证仍由既有后端功能测试负责。旧测量脚本、参数对照表、火焰图及结果文件已移除；后续性能指标由新建的JMeter方案重新定义和验证，本任务未实现该方案。
