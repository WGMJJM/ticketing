# 分阶段开发计划

当前阶段在既有交易、候补、电子票、模块协作及第十阶段退款之上增加第十一阶段的场次工作人员核销权限和管理操作审计。保留MySQL库存、Session/CSRF、电子票签名与Outbox协议，不引入真实支付/退款、微服务或通用RBAC。本阶段测试与联调结果独立记录，不复用旧阶段通过数量。

| 顺序 | 开发范围 | 阶段验收重点 |
| --- | --- | --- |
| 1 已完成 | 活动与场次管理、发布及公开查询 | 已验证公开可见性、状态流转、时间语义、管理权限 |
| 2 已完成 | 票档管理、总库存调整与开售状态查询 | 整数分、库存不变量、父子窗口、权限及并发编辑冲突 |
| 3 已完成 | 用户注册登录、退出、个人中心与管理员权限 | BCrypt、真实Session与Cookie、CSRF、刷新恢复、会话固定攻击防护、越权测试 |
| 4 已完成 | 下单与库存预占、订单查询与主动取消 | 同事务条件库存更新、用户行锁保护跨票档限购、幂等同参/异参、真实HTTP并发、失败回滚与浏览器库存恢复 |
| 5 已完成 | 模拟支付与MySQL超时扫描 | 支付/取消/过期同锁序、数据库截止条件、库存只变一次、唯一真实流水、禁用账号清理、失败隔离与重启补偿 |
| 6 已完成 | 同票档 FIFO 候补与自动调度 | SKU锁内入队、队首阻塞、WAITLIST_CONFIRM、订单终态联动、Outbox确认/租约/重试、真实RabbitMQ死信及数据库补偿 |
| 7 已完成 | 电子票与核销 | 同事务按量出票、受控补票、HMAC轮换/摘要、本人二维码、真实ADMIN扫码及最多一次核销 |
| 8 已完成 | 并发测试与性能评估 | 独立环境52组实测、库存与交易审计、10类故障恢复、发布批量控制实验、完整153项后端回归和Vue真实闭环 |
| 9 已完成 | 架构解耦与工程质量 | 同步事务协作、依赖无环、V5新建及历史升级、161项后端回归、既有五场景及两次候补补测、前端真实闭环 |
| 10 已完成 | 订单运营、整单模拟退款、场次取消善后 | V6保留支付事实，50基础加132真实集成通过；退款/核销竞争、32单并发善后、人工待办、退避与重启补偿、真实管理员/用户页面闭环 |
| 11 已完成开发及隔离验收 | 管理操作审计、场次工作人员核销授权 | 55基础加150真实集成全部通过；V7空库/历史升级、ADMIN/STAFF/USER浏览器联调、撤权并发、审计原子性及三轮核销对照通过。原开发库V7失败现场保留，部署须先人工恢复；详见[阶段11记录](21-staff-audit-checkin-verification.md) |

每阶段补充迁移、真实 API、页面及有意义的测试；不提前生成空层次。真实支付、真实退款、座位图、实名核验、退款对账、多租户、独立IAM和通用RBAC均不在当前计划。性能结论必须来自可复现的压测与一致性核对，不以字段设计、消息发送或静态CHECK测试代替。

第十阶段之后按用户确认整理后端目录：统一扁平controller/service/mapper及其他技术目录，保留全部业务类、接口、事务、SQL和原迁移。第十一阶段再以V7增加场次核销授权与管理审计；不修改V1～V6。同步包引用、测试归属及开发规范，用测试资源登记逻辑模块并继续执行依赖守卫。目录整理验收见[目录整理验收](20-flat-package-refactor-verification.md)，本阶段以测试记录为准。
