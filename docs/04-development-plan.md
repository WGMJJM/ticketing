# 分阶段开发计划

当前阶段完成工程、数据库基线、状态接口、中文展示和开发验证。本轮验收后停止，不自动进入票务业务开发。

| 顺序 | 开发范围 | 阶段验收重点 |
| --- | --- | --- |
| 1 | 活动与场次管理、发布及公开查询 | 只展示已发布活动，时间语义、管理权限测试 |
| 2 | 票档查询与开售窗口 | 价格分、库存可售状态、未到开售时间处理 |
| 3 | 用户注册登录、角色与资源归属 | 密码哈希、认证生命周期、CSRF/Token 明确方案、越权测试 |
| 4 | 下单与锁票 | 同事务条件库存更新、用户场次配额、幂等同参/异参、回滚 |
| 5 | 模拟支付与超时关单 | 支付/超时竞争只允许一方成功，库存只转移/释放一次 |
| 6 | 同票档 FIFO 候补 | 队首策略、重复分配防护、Outbox 和消费者幂等、扫描补偿 |
| 7 | 电子票与核销 | 安全重新展示凭证、持票归属、签名校验、最多一次核销 |
| 8 | 并发测试与性能评估 | 真实场景下库存守恒、无重复业务副作用、故障恢复、实测指标 |

每阶段补充迁移、真实 API、页面及有意义的测试；不提前生成空层次。真实支付、座位图、实名核验、退款对账和多租户均不在当前计划。性能结论必须来自可复现的压测与一致性核对，不以字段设计、消息发送或静态 CHECK 测试代替。
