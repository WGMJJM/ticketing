# 库存预扣与购票结果说明

普通HTTP购票先通过Session、CSRF与用户安全限流，再由Redis Lua原子预扣并取得稳定令牌。MySQL事务持久化购票申请、容量预算与Outbox，HTTP返回202仅表示受理，不代表订单创建成功。

RabbitMQ消费者在MySQL中按账号、活动、场次、用户场次额度、票档、订单的既有锁序核验并创建订单。MySQL仍为订单与库存权威；Redis预扣不替代数据库条件更新、场次限购或幂等约束。

Redis、MySQL、RabbitMQ不构成跨系统强一致事务。失败、超时、取消、退款及库存配置变化须沿用令牌核对、恢复索引、SKU冻结仲裁和数据库事实恢复。无法核对时保持冻结并失败关闭。

候补只在同一SKU内按数据库队首严格FIFO分配，等待期间不占库存或额度。预扣、库存仲裁、事务、缓存与限流使用的业务Lua文件均保留在后端资源目录。

历史百票千人负载数据、结果分类、时序图及复现命令已清理。本说明只保留业务语义，不给出未经重新测量的性能结论。
